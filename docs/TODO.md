## 远期架构

### 用 Go 重写整个服务端

- **提出**：用户，2026-10-23。
- **动机**：Java/Spring Boot + Maven 的构建与常驻资源开销偏大；希望用 Go 单二进制降低服务端内存/启动/部署复杂度。
- **范围（若实施）**：重写 ~~pcl-dsh-server~~ 及 ~~pcl-dsh-core~~ 的业务层（认证/会话/CSRF、REST API、Job/SSE、DSH 反代 HTTP/SSE/WS、账户加密与启动注入、实例/运行时、整合包安全导入导出、插件/目录、文件上传下载、数据 schema）；前端 Vue 与 DSH Node 实例保持不变；发布包改用 Go 二进制 + 静态资源 + 自带 Node/pnpm。
- **需要先评估**：
  - 运行时内存的构成：Maven 只是构建期工具，不是服务器常驻进程；当前 Java 服务 RSS 约 350 MB，而 DSH 的 Node 进程可能占用 1–2 GB。Go 重写主要节省服务端常驻/启动/部署开销，不能消除 Node 侧内存。
  - 迁移成本与回归风险：账户 overlay 依赖 DSH 内部结构、整合包安全归档、反代 token/Cookie/WS、Job/SSE、加密密钥兼容、数据 schema 兼容、前端 API 兼容等。
  - 建议先做内存/启动剖析与“保留 Java、仅优化 JVM/构建”的对比，再决定是否值得整体重写。
- **状态**：未排期，待讨论。
